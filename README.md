# dsh-bigger-choice

把输入框右下角那个**内置模型选择器**的下拉框做大做清楚：一屏能直接看到十几个模型，并且随时看得出「这批模型属于哪个提供商」。

纯客户端插件：不碰任何宿主代码——往页面里注入一份样式表（放大弹层），再在模型面板的
搜索框右侧注入「免费」「收藏」两枚按钮，筛选和排序都在页面里用 DOM 完成。装完即生效（刷新页面后）。

## 它改了什么

内置下拉框由 `@deepseek-ai/dsh-client-ui-model-selection` 渲染，宿主对它的尺寸写死了上限：

| | 原生 | 本插件 |
|---|---|---|
| `max-height` | `min(360px, 100vh - 96px)` | `min(78vh, 100vh - 24px)` |
| `width` | `max-content`（跟着内容） | `max-content`（重申，别被拉走） |
| `min-width` | `min(240px, 100vw - 32px)` | `min(240px, 100vw - 24px)`（保留原下限） |
| `max-width` | `min(420px, 100vw - 32px)` | `min(720px, 100vw - 24px)` |

行高（34px）不动，所以 756px 高的窗口里可见行数从约 10 行涨到约 15–16 行；窗口越高看到越多。

**宽度是自适应的**：宿主本来就给弹层 `width: max-content`——最长的一行（模型名或提供商名 + 末尾的打勾）有多宽，弹层就有多宽。第一版把它连同 `min-width` 一起撑到 360px，于是每行都空出一道「名字 → 打勾」的空白。现在 `min-width` 退回 240px 这个原下限，宽度重新由内容决定；`max-width` 只兜住超长名字，不让弹层拉穿视口。

> 已知边界：列表长到需要滚动时，竖直滚动条会吃掉内容区约 8px 宽，**最长的那个名字**可能因此被省略号截掉一两个字符。这是「宽度跟随内容」与「滚动条占位」的固有矛盾（滚动条不参与 `max-content` 计算），代价最小的一侧就是放过最长那一行。

## 提供商名（分组标题）

「CodeArts Agent」「CodeBuddy（腾讯）」这类行是 `MenuGroup` 渲染的 sticky 标题，
宿主样式是 **11px / `label-tertiary` 灰字 / 透明底**，只有真正吸顶那一刻才铺一层底色——
所以平时几乎看不见，也就分不清某个模型属于谁。本插件把它改成一条常驻色带：

| | 原生 | 本插件 |
|---|---|---|
| 字号 / 字重 | 11px / 500 | 12px / 600 |
| 颜色 | `--dsw-alias-label-tertiary` | `--dsw-alias-label-primary` |
| 背景 | 透明（仅吸顶时铺色） | 常驻 `--dsw-alias-menu-group-header-fill` |
| 内边距 | `4px 7px 2px` | `8px 8px 5px` |
| 组间距 | `3px` | `8px` |
| 下沿 | 无 | 1px `--dsw-alias-border-l2` |

关键是**常驻**：色带一直钉在列表顶部，所以「眼下这批模型属于哪个提供商」永远看得见，
不用往回滚去找那一行。吸顶时不再变色，也就没有滚动闪烁。

选择器在这里**不用 hash**——`MenuGroup` 会给标题打 `data-menu-group-heading`，
宿主自己的 `observeStickyMenuGroups()` 就是靠这个属性找分组的，属于它自己的契约面，
升级不会变。外面仍然限定在模型选择器的弹层里（用滚动容器的 `id$="-models"` 收窄），
不会波及别处恰好也用 MenuGroup 的菜单。

## 「免费」按钮与价格排序

模型面板（点开选择器、再进「模型」那一层）的搜索框右侧多出一枚 **「免费」** 按钮：

* **点选后**：只显示免费模型。免费的判定（名字里出现以下任一条）：含 `free`（不分大小写）、
  含 `0.00`、含「免费」，或价格标注为 `x0.00`。没有免费模型的提供商整组隐藏（连色带一起），
  一个都不剩时列表里出现一行「没有免费模型」，点它可以一键复位（清掉搜索词 + 取消免费）。
* **取消后**：不做任何免费过滤，12 个提供商组与全部模型原样回来——**提供商色带始终保留**。
* 按钮同时服从搜索：搜索词 + 免费可以叠加；搜索框出现清除按钮时，按钮自动右移到
  `right: 32px` 避让，不会互相压住。

每个提供商组内部按「**免费 → 价格从低到高 → 无价格垫底**」排序（同价位保持原有顺序）：

| 模型名样例 | 归类 |
|---|---|
| `Step 5 Preview · 免费` / `Auto-Free` | 免费，排最前 |
| `Hy3 · x0.00→免费` | `x0.00` 也判免费，排最前 |
| `GLM-5-3 · x0.06` | 有价格，按 `0.06` 升序 |
| `DeepSeek-V4.1-Flash · x0.25` | 有价格，`0.25` 排在 `0.06` 之后 |
| `qwen3.6-plus` | 没有 `x` 价格标注 → 该组**最末** |

价格只认 `x<小数>` 这一种标注（宿主名里的版本号 `V4.1`、`M2.5`、`1.13` 都不含 `x` 前缀，
不会误判成价格）。排序是稳定排序：同组内同价位的模型保持宿主给的原始顺序。

实现要点：**只重排 DOM、不改宿主状态**。菜单每次重渲染（换层、改搜索词、滚动重定位）
之后由一个 MutationObserver 兜住，在微任务里批量重排一次；分组信息全部读宿主自己打的
`data-menu-group` / `data-menu-group-heading` 契约，按键导航（↑↓ / Enter）走的仍是宿主的
React 状态，注入的按钮不参与焦点链，键盘操作不受影响。

## 「收藏」：行尾星星与收藏筛选

模型面板的每一行右侧都挂着一枚星星（悬停时才显形，已收藏的常亮）：

* **点星星**收藏/取消收藏这一行——**不会顺手选中模型**（行是 `<button>`，宿主的 `onClick`
  在 root 上委托，星星这一层把 `click` / `mousedown` / `pointerdown` 全部拦下）。
* 收藏写在 `localStorage`（键 `dsh-bigger-choice:favorites`，键名格式
  `提供商::模型显示名`），**刷新、关弹层、重开都在**。
* 已收藏的行：整行铺一层琥珀色底（`--dsh-bigger-choice-fav-bg`），星星变成实心。
  键盘高亮（`data-highlighted`）的行不铺这层底色，让给宿主自己的高亮样式。
* 行尾的星星是最后一个 flex 子元素，跟着 `max-content` 一起把弹层**撑宽**（约 +24px），
  不用改任何尺寸规则。
* 搜索框右侧的第二枚按钮 **「收藏」**：只显示已收藏的模型；没有收藏的组整组隐藏，
  一个都不剩时出提示「没有收藏的模型」，点它一键复位。
* 「免费」与「收藏」**是 AND 关系**，可以同时开：只剩「既是免费、又已收藏」的模型；
  两边叠加后为空时提示「没有免费且已收藏的模型」，点一下两枚开关一起复位。
* **收藏不参与排序**：收藏的模型不会因此被顶到提供商列表顶部，仍按价格规则待在原位。

实现要点与「免费」同源（DOM 级、契约面读取、微任务批处理）。两个易踩的坑已经处理：

* 宿主重渲染整行时会**重置 `className`**，我们补上的 `.dshbc-fav` 会被抹掉——观察器因此
  额外盯着 `class` 属性变更，刷回来（只盯 `class`，不盯 `style` 等其他属性：宿主的定位
  测量会反复写 inline style，无条件盯属性会形成观测回环把页面跑死）。
* 点星星时浏览器会把焦点挪到行按钮；取消收藏后该行若被立刻筛掉，**隐藏已聚焦元素会触发
  blur，宿主会顺着它把整个弹层关掉**——行将被藏起来时，先把焦点交还搜索框再刷新列表。

## 尺寸：为什么改样式表就够了

弹层是 React portal（`position: fixed`），但**位置和尺寸都是宿主自己算的**：弹出前先
`menuRef.current.offsetHeight` 量一次，再把 `top` 夹进视口（`MARGIN = 12`），并在
`scroll` / `resize` 时重算。我们的样式表在插件加载时就已生效，所以宿主第一次量到的
就是放大后的高度，它会自己把菜单摆正——不会顶出屏幕，也不需要我们碰 `top/left`。

## 弹层的选择器

```css
._7KE1Ra_menu,
[id$="-menu"][class*="_menu"]:has([class*="_groups"]) { … }
```

* `._7KE1Ra_menu`：本机这一版 DSH 构建出的 CSS-module 类名（hash 由源码内容决定）。
* 第二条是 **DSH 升级后的兜底**：hash 变了也没关系——宿主给弹层的 id 是自己拼的
  `id={id}-menu`，而 `_menu` / `_groups` 是该模块**本地**的类名（本地类名不变则后缀不变）；
  再要求弹层里真的装着那个滚动容器，避开其它恰好叫 `*_menu` 的弹层。

两条都靠 CSS-module 的 `<hash>_<localName>` 命名约定，不改任何宿主代码。

## 想再调大/调小、想换标题色

七个旋钮都走 CSS 自定义属性，devtools 或你自己的样式表里覆盖即可，不用重装：

```css
:root {
  /* 弹层尺寸 */
  --dsh-bigger-choice-max-height: min(90vh, 100vh - 16px);
  --dsh-bigger-choice-min-width: min(320px, 100vw - 24px);
  --dsh-bigger-choice-max-width: min(760px, 100vw - 24px);
  /* 提供商标题栏 */
  --dsh-bigger-choice-group-color: var(--dsw-alias-label-secondary);
  --dsh-bigger-choice-group-size: 13px;
  /* 收藏星星与收藏行底色 */
  --dsh-bigger-choice-star-color: var(--dsw-alias-state-warn-primary);
  --dsh-bigger-choice-fav-bg: var(--dsw-alias-state-warn-tertiary);
}
```

想让每行都空出固定宽度（例如把「名字 → 打勾」那块拉开），把 `min-width` 调大即可——
宽度本来跟着内容走，`min-width` 一抬高就成了一条固定的下限。

## 结构

| 文件 | 作用 |
|---|---|
| `package.json` | bundle 元数据（`dsh.bundle.patch` + `dsh.client`） |
| `cordis.patch.yml` | 插入一行 `dsh-bigger-choice` |
| `index.js` | 宿主半身，空实现（本插件不需要宿主服务） |
| `client.js` | 客户端半身：注入样式表 + 「免费」「收藏」两枚按钮（筛选 / 排序 / 收藏）的 DOM 控制器 |
| `icon.svg` | 图标 |

## 已知边界

* 这是**刻意覆盖宿主弹层**，不是官方插槽能力：`_7KE1Ra_menu` 这个 hash 会随 DSH 升级变化，
  届时靠第二条选择器继续命中；若某次升级连 `_menu` / `_groups` 的本地类名也改了，需要重新对一次。
* 只放大「模型选择器」这一个弹层。宽度是自适应的（跟随最长一行），模型名不会换行。
* 提供商色带是**常驻**的：宿主原本只在吸顶时铺底色，这里改成一直铺。如果你更想要宿主的
  原行为（只在吸顶时铺色），把那一行的背景换成透明即可。
* 「免费」按钮只出现在**模型面板**（有搜索框那一层）；根面板与推理档位面板没有搜索框，
  不会注入。宿主 `choices.length > 4` 才显示搜索框，模型少于 5 个时按钮也不出现——这是
  跟随宿主自己的显隐规则，不算失效。
* 星星同样只出现在模型面板；收藏按 `localStorage` 存（无痕模式 / 清理站点数据会清空
  收藏，其它功能不受影响）。
* 筛选让弹层变矮 / 变高后，**弹层位置会跟着重算**（可见性真的变化时向 window 派发一次
  scroll，宿主的定位 effect 挂在 window 捕获 scroll 上，只依赖 open/pane/state/query，
  我们改 DOM 不会触发它——不通知的话弹层会停在旧位置甚至探出屏幕）。
* 免费判定只看**显示名**。若哪天某个免费模型的显示名里既没有 `free` / `免费` / `0.00`，
  也没有 `x0` 价格，它会被漏掉——判定规则与用户口径一致，不额外猜。
* 价格排序只认 `x<小数>` 标注；没有该标注的名字一律垫底，不做任何语义猜测。

## 验证到什么程度

* 宿主侧：`cordis.yml` 里已落行（`- id: dsh-bigger-choice` / `name: dsh-bigger-choice`，无
  `disabled`），运行中的 Loader 也能查到这条 entry（`include:dsh-bigger-choice`，
  `status: absent`＝无 Config，正常）。
* 语法：`node --check client.js` 通过。
* 真实浏览器（无头 Brave，复用 `~/.dsh/browser-profile` 里带登录态的会话，打开本机 GUI
  `http://127.0.0.1:3080`，新开会话 → 点开模型选择器 → 进「模型」面板）逐项实测：
  * 模型面板里注入成功：`.dsh-bigger-choice-free-toggle` 存在、文字「免费」、`aria-pressed`
    随点击翻转；
  * **排序**：679 个可见模型逐组断言「免费在前 → `x` 价格升序 → 无价格垫底」，**0 违规**；
  * **筛选**：点「免费」后只显示免费模型，没有免费模型的组整组 `display: none`（含色带），
    其余组的色带保留；再点一次全部回来，排序仍在；
  * **叠加搜索**：免费态下搜索框输入正常过滤，清除按钮出现时按钮右移到 `right: 32px`
    避让；无匹配时出现「没有免费模型」提示，点它一键复位；
  * **收藏**：679 行每行恰好一枚星星（无重复、无遗漏），行尾排列为
    `[名字, 打勾, 星星]`；悬停显形（opacity 0.5）、点星星后该星星常亮（opacity 1）且
    **不改变当前选中模型**（触发器文字不变、弹层不关）；
  * **收藏持久化**：刷新页面后重开弹层，收藏仍在（`localStorage` 键
    `dsh-bigger-choice:favorites`，格式 `提供商::模型显示名`），`.dshbc-fav` 类与琥珀底色
    一并恢复；
  * **收藏筛选**：点「收藏」后只剩收藏的模型（1 行可见，其余 16 个组整组隐藏）；与「免费」
    叠加为 AND——收藏的免费模型只剩那 1 行，收藏的非免费模型则全部隐藏并出提示
    「没有免费且已收藏的模型」，点提示两枚开关一起复位；
  * **收藏不改排序**：收藏的模型仍待在价格序原位，不被顶到组顶；
  * **宿主重渲染不丢类**：悬停别的行触发宿主重渲染（会重置行 `className`）后，收藏行的
    `.dshbc-fav` 类与底色仍在；
  * **取消收藏不误关弹层**：筛选态下点掉最后一行的星星（该行随即被筛掉），弹层保持打开、
    空态提示正常出现；
  * **筛选后弹层重定位**：点「收藏」弹层从 707px 缩到 110px 时位置随动（top 12→400，
    锚在触发按钮上方）；再点掉筛选弹层长回 707px 时位置重算回 top 12（不重算的话会停在
    400 处、底部探出屏幕）；「免费+收藏」空态（h=73，top=437）与点提示复位两路同样随动；
  * 截图：`docs-free-on.png`（免费态，96,548 字节）留在插件目录里备查。
* 没做：不同窗口尺寸 / 不同缩放下的视觉回归截图，以及键盘导航（↑↓ / Enter 选模型）在注入
  按钮后的端到端回归——注入节点不参与 React 焦点链，但未逐键实测。
